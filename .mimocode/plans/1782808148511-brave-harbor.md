# Plan: 报销人支持 + 报销类别自动匹配

## 需求概述
1. 工作目录下按报销人建子文件夹，子文件夹里放发票PDF
2. 导入时递归扫描子目录，从父文件夹名提取报销人
3. 表格显示报销人列
4. 报销类别通过 mapping.json 的项目名称模式自动匹配，移除手动设置功能
5. 用户只能通过「修改报销类别」编辑 mapping.json 来间接改变分类

## 修改文件清单

### 1. `src-tauri/src/commands/mod.rs` — 改造 list_pdfs 命令
- **当前**: `list_pdfs(path)` 只扫描顶层目录的 PDF 文件
- **改为**: 递归扫描，返回 `Vec<PdfEntry>` 包含文件路径和报销人
- 新增结构体 `PdfEntry { path: String, owner: String }`
- **目录结构**（实测）:
  ```
  工作目录/
    ├── *.pdf          → owner = ""
    ├── 丁斌/
    │   └── 发票明细/
    │       └── *.pdf  → owner = "丁斌"
    ├── 毛小军/
    │   ├── 荆州/
    │   │   └── *.pdf  → owner = "毛小军"
    │   └── 武汉/
    │       ├── *.pdf  → owner = "毛小军"
    │       └── ETC发票/
    │           └── *.pdf → owner = "毛小军"
    └── 徐胜/
        └── 5月份发票/
            ├── *.pdf  → owner = "徐胜"
            └── 通行费电子发票/
                └── *.pdf → owner = "徐胜"
  ```
- **算法**: 
  1. 扫描工作目录根下的 PDF 文件 → owner = ""
  2. 扫描工作目录根下的子文件夹 → 文件夹名即 owner
  3. 递归扫描子文件夹下所有层级的 PDF（任意深度），均归为该 owner
  4. 忽略非 PDF 文件（jpg, xlsx, zip 等）

### 2. `src-tauri/src/invoice_parser.rs` — 添加报销人字段 + 自动匹配
- `ParsedInvoice` 新增 `pub owner: String` 字段（报销人）
- `import_invoices` 签名改为接收 `Vec<PdfEntry>` 而非 `Vec<String>`
- 解析时将 `owner` 从 `PdfEntry` 传入
- **新增** `match_category` 函数：读取 mapping.json，用 `项目名称` 字段（支持 `*通配符*` 和 `|` 分隔的多模式）匹配发票的 `project_name`，返回对应的 `报销类别`
- `parse_one` 内调用 `match_category` 自动填充 `category`

### 3. `src-tauri/src/commands/mod.rs` — 更新 import_invoices 命令
- 接收新的 `PdfEntry` 列表
- 解析前加载 mapping.json，传给解析器做自动匹配

### 4. `src/App.jsx` — 前端改造
- **list_pdfs 调用**: 接收新的 `PdfEntry[]` 结构，传递 owner 信息
- **importInvoices**: 将 owner 信息带入 invoices state
- **表格**: 新增「报销人」列（在文件名列之后）
- **移除**: 一键设置类别按钮、bulkCategory state、bulkSetCategory 函数
- **报销类别列**: 改为纯文本显示（不可编辑），无匹配时显示「(未匹配)」
- **筛选行**: 报销类别下拉改为筛选功能（类似购买方下拉），新增 `categoryFilter` state
- **新增**: `categoryOptions` useMemo — 从 invoices 中提取已匹配的非空报销类别（去重排序）
- **filtered useMemo**: 增加 `categoryFilter` 筛选条件

### 5. `src-tauri/src/config_store.rs` — 无需改动
mapping.json 的读写逻辑不变，只是现在被解析器消费了。

## 实现步骤

### Step 1: Rust 后端 — 改造 list_pdfs
- 修改 `list_pdfs` 返回 `Vec<PdfEntry>`
- 递归扫描：先扫工作目录根下PDF，再遍历子文件夹取文件夹名为 owner，扫描其下PDF

### Step 2: Rust 后端 — ParsedInvoice 添加 owner 字段
- 结构体加 `pub owner: String`
- `parse_one` 接收 owner 参数

### Step 3: Rust 后端 — 实现自动匹配逻辑
- 新增函数 `match_category(project_name: &str, mappings: &Vec<MappingEntry>) -> String`
- 匹配规则：mapping 的 `项目名称` 字段支持 `*` 通配和 `|` 分隔多模式
- 将 `*xxx*` 转为正则 `.*xxx.*`，多个模式用 `|` 连接
- 在 `import_invoices` 中先加载 mapping.json，再逐文件解析并匹配

### Step 4: Rust 后端 — 更新 import_invoices 命令签名
- 接收 `entries: Vec<PdfEntry>` 替代 `paths: Vec<String>`
- 内部加载 mapping，传给解析器

### Step 5: 前端 — 适配新的 list_pdfs 返回值
- `importInvoices` 中处理 `PdfEntry[]`，每项带 `path` 和 `owner`
- 传递 owner 到 invoices state

### Step 6: 前端 — 表格增加报销人列
- 在文件名列后增加报销人列

### Step 7: 前端 — 移除手动设置类别，改为筛选
- 删除 bulkCategory state、bulkSetCategory 函数
- 删除一键设置类别的按钮和下拉框
- 新增 `categoryFilter` state（默认空=全部）
- 新增 `categoryOptions` useMemo：从 invoices 中提取已匹配的非空报销类别，去重排序
- 筛选行新增报销类别筛选下拉：`<select value={categoryFilter}>` 选项为「报销类别(全部)」+ categoryOptions
- filtered useMemo 增加：`if (categoryFilter) rows = rows.filter(r => r.category === categoryFilter)`
- 报销类别列改为纯文本，无匹配显示「(未匹配)」

## 验证方式
1. `npm run tauri:dev` 启动应用
2. 工作目录选择 `测试数据/` 文件夹
3. 点击发票导入，验证：
   - 根目录 PDF 被导入（报销人为空）
   - 丁斌/发票明细/ 下 16 个 PDF 被导入，报销人=丁斌
   - 毛小军/荆州/ 下 14 个 PDF 被导入，报销人=毛小军
   - 毛小军/武汉/ 下 15+1 个 PDF 被导入，报销人=毛小军（含 ETC发票/ 子目录）
   - 钱松驰/发票明细+支付凭证/ 下 PDF 被导入（忽略 jpg），报销人=钱松驰
   - 徐胜/5月份发票/ 下 PDF 被导入（忽略 xlsx, zip），报销人=徐胜
   - 非 PDF 文件（jpg, xlsx, zip）不被导入
   - 报销类别根据 mapping.json 自动匹配
4. 验证表格中无手动设置类别的控件
5. 验证报销类别筛选下拉正常工作
6. 验证「修改报销类别」编辑 mapping 后重新导入能生效
